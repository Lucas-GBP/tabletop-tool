# Repository Instructions

This repository is a Tauri v2 desktop app with a SolidJS + TypeScript + Vite
frontend and a Rust backend. Use this file as the first stop for future coding
agents.

## Start Here

- Read `.codex/project-context.md` before non-trivial work.
- For audio mixer changes, also read `.codex/audio-mixer.md`.
- For validation choices, read `.codex/verification.md`.
- Check `git status --short` before editing. The worktree may already contain
  user changes; preserve them.

## Project Shape

- Frontend lives in `src`.
- Tauri/Rust backend lives in `src-tauri`.
- The current app shell renders the audio mixer as the active tool.
- Tauri commands are called from TypeScript through `@tauri-apps/api/core`.
- SQLite persistence is implemented on the Rust side.
- `src/bindings/tauri/*.ts` files are generated by `ts-rs`; do not edit them by
  hand.

## Working Rules

- Keep changes scoped to the module that owns the behavior.
- Follow existing SolidJS patterns: signals/accessors, TS strictness, SCSS
  modules, and no React-style state assumptions.
- Use shared helpers instead of duplicating validation or parsing logic.
- Keep new docs and code ASCII unless the file already clearly uses a different
  encoding.
- Do not introduce scene/composition behavior into the audio mixer. The mixer
  owns the library/editor flow only.

## Audio Mixer Rules

- The current domain flow is:
  `audio file -> audio object -> audio object list`.
- Reusable audio-region behavior belongs in
  `src/tools/audio-mixer/audio/audioRegions.ts`.
- Waveform dragging, preview seeking, and text inputs must share the same region
  semantics.
- Numeric inputs that normalize values should allow draft text while editing and
  commit on blur/Enter. Escape should cancel back to the stored value.
- When playback-relevant audio object settings change, preview state may need to
  stop or restart deliberately.

## Common Commands

- Frontend dev server: `npm run dev`
- Full Tauri dev app: `npm run tauri dev`
- Frontend build: `npm run build`
- Frontend lint: `npm run lint:ts`
- Rust lint: `npm run lint:rs`
- Full check: `npm run check`
- Rust tests and `ts-rs` export checks: `cd src-tauri && cargo test`

If Rust exported structs change, regenerate/check the bindings through the Rust
flow, then format generated TypeScript with Prettier if needed. Do not manually
rewrite generated binding files.
